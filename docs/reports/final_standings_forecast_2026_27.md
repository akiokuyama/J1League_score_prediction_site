# 2026/27 J1 最終順位予測の実装記録

## 目的

試合単位の予測に加え、予測した日時を残しながらシーズン最終順位の見通しを毎週確認できるようにする。

## 計算方法

1. 終了済み試合の得点、失点、勝点を実績として固定する。
2. 残り試合ごとに、公開予測の期待得点と勝敗確率から整合するスコア分布を作る。
3. 残り全試合を10,000回抽選する。
4. 各回で勝点、得失点差、総得点の順に順位を付ける。これらも同じ場合は、特定チームに有利にならないよう固定シードの乱数で順序を決める。
5. チームごとに期待勝点、平均順位、10〜90パーセンタイル順位、優勝・Top 3・下位3の確率を集計する。

通常のリーグ戦は勝利3点、引き分け1点、敗戦0点として計算する。公式の順位決定方法は勝点、得失点差、総得点、当該チーム間成績、必要時の抽選の順だが、本実装は計算量と説明可能性を優先し、当該チーム間成績を省略して完全同値を乱数処理する。このため表示は確定順位ではなく確率的な参考予測である。

参考: [Jリーグ公式サイト 大会概要](https://www.jleague.jp/outline/j1.html/j2-playoff.html)

## 出力

- `outputs/standings_forecast/latest.json`: Streamlitが最初に表示する最新予測
- `outputs/standings_forecast/history/standings_forecast_YYYYMMDD_HHMMSS.json`: 予測時点ごとの履歴

JSONには以下を記録する。

- 生成日時
- 終了済み試合の基準日と試合数
- モデルバージョン
- シミュレーション回数と乱数シード
- 日程件数と暫定補完件数
- チーム別の順位・期待勝点・順位確率

## UI

トップレベルの表示切替に「最終順位予測」を追加した。予測日時を選ぶと、その時点での予測を表示する。

各クラブについて以下を表示する。

- 予測順位とロゴ
- 現在順位と予測順位との差
- 期待勝点
- 優勝確率
- Top 3確率
- 下位3確率
- 順位分布の10〜90パーセンタイル

開幕前は実績による現在順位が存在しないため、現在順位と順位変動は `-` とする。

## 2026年7月20日時点の日程不足

取得済みの公式日程は379試合で、20クラブのホーム＆アウェイ総当たりに必要な380試合より1試合少ない。未収録は京都ホーム対岡山である。

正式日程が入るまで、順位予測だけは岡山ホーム対京都の予測についてホーム・アウェイを入れ替え、期待得点と勝敗確率を反転して暫定補完する。UIとJSONの両方に警告を残す。公式日程と実試合予測が取得できた時点で、この補完は自動的に不要になる。

## 定期更新

水曜07:00 JSTの予測更新と手動予測更新で、試合予測生成後に以下を実行する。

```bash
python scripts/build_standings_forecast.py \
  --matches Data/processed/matches_2026_27_j1_clean.csv \
  --predictions outputs/all_unplayed_predictions.json
python scripts/validate_standings_forecast.py
```

月曜の結果更新ワークフローは試合予測を作り直さないため、順位予測も更新しない。週次スナップショットの基準時点は水曜の予測更新後となる。

## 検証

- 予測順位が1位から20位まで重複なく存在すること
- 各確率が0〜1に収まること
- 各チームの順位確率の合計が1になること
- 全クラブの優勝確率合計が1、Top 3確率合計が3、下位3確率合計が3になること
- 日程不足時に逆カード補完と警告が生成されること
- PC幅とスマートフォン向けレイアウトで列が崩れないこと
