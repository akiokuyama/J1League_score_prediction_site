## どのようなアプリを作ったのか

今回作成したアプリでは、主に以下の内容を確認できます。

- J1リーグの予測スコア
- ホーム勝利・引き分け・アウェイ勝利の確率
- スコア候補Top 5
- 得点者候補
- 過去の予測と実際の試合結果
- 10,000回のシミュレーションによる最終順位予測

スマートフォンでは、ホーム画面に追加して普通のアプリのように使うこともできます。

マイチームを設定すると、アプリを開いた瞬間からそのチームの試合だけが表示されます。ライトモードとダークモードも切り替えられます。

また、試合データの取得、特徴量の作成、予測結果の更新も自動化しました。

我ながら、最初に想像していた「簡単に動くアプリ」よりも、だいぶ大きなものになってしまいました。

## 開発のきっかけ：なぜJリーグの試合予測アプリを作ろうとしたのか

これまで機械学習や統計学の勉強はしてきたものの、アプリ開発のようなエンジニアリングの勉強は全くしてきませんでした。

しかし、AIがこれだけ発達した今なら自分にもできるのではないか。多少知識が足りなくても、簡単に動くアプリ程度ならAIを使って作成できるのではないかと思い、挑戦してみることにしました。

もう一つの理由は、私自身がJリーグの大ファンだからです。

2022年にアメリカへ渡る前のニート期間、暇つぶしにJリーグの試合を見に行ったことをきっかけに、すっかり沼にはまってしまいました。

アメリカにいる間も毎シーズン、一時帰国するたびにスタジアムへ足を運び、現地からもずっとマイチームを応援し続けていました。

世の中には、野球や競馬の結果を予測するAIや機械学習のサイトはたくさんあります。

一方で、Jリーグの試合予測に特化したアプリやサイトは、私が探した範囲では見当たりませんでした。

「ないなら自分で作ってみたい」と思ったのが、開発の直接的なきっかけです。

## 予測モデルはどのように作ったのか

ここからは、今回作成した予測モデルの概要について簡単に解説します。

「AIによる試合予測」と書いていますが、ChatGPTに「次の試合は何対何ですか？」と質問しているわけではありません。

過去の試合データから機械学習モデルを作り、そのモデルを使って得点や勝敗の確率を計算しています。

### 予測に使っているデータ

学習には、2021年から2025年までの通常のJ1リーグと、2026年に行われた百年構想リーグのデータを使いました。

合計1,952試合です。

モデルには、チームの順位、勝点、直近の成績、Eloレーティング、フォーメーション、選手やチームの攻撃指標、市場価値、休養日、移動距離など、156個の特徴量を入力しています。

ここで大事なのは、「試合が始まる前に分かる情報だけを使う」ことです。

開発途中では、実際の観客数が学習データに入っていることが分かりました。

実際の観客数は試合が終わった後に確定するデータなので、予測時には分かりません。これを学習に使うと、未来の情報をカンニングする「データリーク」になってしまいます。

そのため、実績観客数や収容率はモデルから削除しました。天候データも、取得や更新が不安定な割に精度への貢献が小さかったため、現在のモデルでは使っていません。

モデルを複雑にするよりも、予測時点で本当に取得できるデータだけを使うことの方が重要だと、改めて感じました。

### まずは両チームの得点を予測する

モデルは、LightGBMという機械学習の手法を使って、ホームチームとアウェイチームの期待得点を予測します。

例えば、ホームチームの期待得点が1.5点、アウェイチームが1.0点と予測されたとします。

もちろん、実際の試合が1.5対1.0で終わることはありません。

そこで、サッカーの得点がポアソン分布に従うと仮定して、

- 0-0になる確率
- 1-0になる確率
- 1-1になる確率
- 2-1になる確率

というように、0点から8点までの全てのスコアの確率を計算します。

その中で最も確率が高い組み合わせを「予測スコア」として表示しています。

さらに、ホームチームが勝つスコアを全て足せばホーム勝利確率、同点のスコアを足せば引き分け確率、アウェイチームが勝つスコアを足せばアウェイ勝利確率になります。

この方法なら、予測スコア、スコア候補Top 5、勝敗確率を全て同じ計算から出すことができます。

### 最終順位も10,000回予測する

最終順位予測では、残りの全試合を10,000回シミュレーションしています。

1回のシミュレーションごとに、各試合の勝敗を先ほどの確率に基づいて決め、勝点を加算します。

これを10,000回繰り返すことで、

- 予想順位
- 期待勝点
- 優勝確率
- Top 3に入る確率
- 下位3チームに入る確率

などを計算しています。

毎週の予測結果も保存するため、シーズン終了後には「開幕前の予測はどれくらい当たっていたのか」「何節くらいから順位予測が安定したのか」を振り返る予定です。

## AIに作ってもらったもの

最初は、予測結果を一覧で表示できるだけの簡単なWebアプリを作る予定でした。

しかし、作っているうちに欲が出てきました。

最終的には、AIに指示を出しながら以下の機能を追加しました。

- Webアプリの画面作成
- チームロゴの表示
- マイチーム機能
- スマートフォン向けPWA
- ホーム画面への追加機能
- 最終順位予測
- GitHub Actionsによるデータの定期更新
- Google Analyticsによる利用分析

エラー画面のスクリーンショットをAIに渡して、

「ここが動かない」

「スマホだと表が崩れている」

「ホームチームの勝ちばかりに見えて面白くない」

などと伝えると、AIが原因を調査してコードを修正してくれます。

私はコードを1行ずつ書くのではなく、作りたいものを説明して、動作を確認し、違和感があれば修正を依頼する役割でした。

これはプログラミングというより、AIに対するディレクションに近かったです。

## AIの逆襲：自分のモデルよりAIのモデルの方が強かった

開発の中で最も面白かったのは、アプリではなく予測モデルの改善でした。

最初は、自分が作った勝敗分類モデルと得点差モデルを組み合わせて、最終的な予測スコアを決めていました。

しかし、この方法では、それぞれのモデルが別々の答えを出すため、「予測スコアはホーム勝利なのに、勝敗確率ではアウェイ勝利」のような分かりにくい結果が出ることがありました。

そこで、ChatGPT（GPT-5.5）に別の方法を考えてもらいました。

提案されたのが、先ほど説明した「期待得点から全スコアの確率分布を作る方法」です。

2026年の百年構想リーグ後半71試合で比較すると、結果は以下のようになりました。

| モデル | 勝敗の的中率 |
| --- | ---: |
| 以前の勝敗分類モデル | 38.0% |
| AIが提案したスコア分布モデル | 49.3% |

完全なスコアまで当てられた割合は16.9%でした。

評価対象が71試合と少ないため、この結果だけで常に優れているとは言えません。

それでも、自分が試行錯誤してオリジナルで構築したモデルより、ChatGPTに考えてもらったモデルの方が、はるかに良い精度になりました。

自分が時間をかけて作ったモデルがAIにあっさりと敗北してしまったのは、悔しくもあり、どこか笑ってしまうような体験でした。

## 作ってみた感想：データ通りにいかない面白さ

実際に作ってみて感じたのは、「意外と予測が当たらないな」ということです。

勝敗の的中率が約半分と聞くと、それなりに当たっているようにも思えます。

しかし、実際に1試合ずつ予測と結果を見比べると、「この試合を外すのか」「なぜこのチームが負けるのか」という試合がたくさんあります。

ただ、これは決して悪いことではありません。

自分にとってサッカーは、戦術を細かく分析して見るものというより、ピッチ上で繰り広げられるストーリーや選手の気持ちを感じるスポーツです。

だからこそ、あえて戦術解説には詳しくなりすぎないようにして、純粋な感情移入を楽しんできました。

データによる予測がそこまで当たらないというのは、サッカーの持つドラマ性を証明しているようで、むしろ自分にとっては好ましい結果でした。

退場者が出たり、スーパーゴールが決まったり、終了間際に劇的な逆転が起きたりします。

選手の気持ち、スタジアムの雰囲気、監督の采配、偶然のバウンドなど、モデルに入れられないものが試合結果を左右します。

全てがデータ通りに決まるのであれば、サッカーはここまで面白いスポーツではないと思います。

## 最後に：AI時代の個人開発と、これからの趣味のあり方

今回の開発を通じて、アプリ作りを新しい趣味にできるかもしれないと期待していました。

しかし結論から言うと、これは趣味にはなり得ないなと感じています。

自然言語で指示を出すだけで、AIが勝手にコードを書いてアプリを完成させてくれます。

私のようにエンジニアリングの知識がなくても、フロントエンドが動くレベルや、そこまで高度なサービス品質を求めないものであれば、誰でも簡単に作れてしまいます。

その結果、試行錯誤してようやく動いたときの「モノづくりの喜び」のようなものは、すっかり薄れてしまいました。

コードが動いて感動することはもうなく、むしろ「なぜAIはこれくらいのバグを解決できないんだ」と、思い通りに動かないAIに対してイライラすることの方が多くなってしまったのです。

今後は、これまでの開発スピードとは比較にならない速さで、プログラミング未経験の素人が作ったアプリやWebサービスが世の中に溢れ返るのだろうと思います。

だからといって、自分はこれを副業にしたいとは思いません。

本業と全く違う畑のことであれば副業にするのもありですが、アプリ開発を副業にしてしまうと、365日ずっとパソコンの前に張り付き、AIに指示を出し、コードを修正し続ける生活になってしまいます。

それは、自分が本当にやりたい時間の使い方ではないなと、改めて実感しました。

一方で、「こんなものがあったら面白い」と思ったものを、自分で形にできる時代になったことは素晴らしいと思います。

アプリ開発自体を趣味にはできなくても、Jリーグ観戦という元々の趣味を少し面白くする道具を、自分で作ることはできました。

これから新シーズンが始まります。

予測が当たったときは少し喜び、外れたときはサッカーの面白さを感じながら、アプリと一緒にJリーグを楽しみたいと思います。
